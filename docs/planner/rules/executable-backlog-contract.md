# Executable Backlog Contract

A backlog is executable only when a developer and reviewer can determine what to produce and how completion will be demonstrated without inventing missing behavior.

## Milestone contract

- Outcome
- Features and status
- Run or verification workflow
- Expected result
- Failure verification proportional to risk
- Exit criteria
- Review evidence bundle

## Feature contract

- Outcome
- Scope and non-scope
- Linked executable tasks
- Run or verification workflow
- Expected result
- Failure scenarios
- Acceptance criteria
- Review evidence

## Task contract

Use the task template. Every implementation task must identify outcome, scope, non-scope, artifacts, dependencies, run, expected result, failure scenarios, acceptance criteria, and evidence.

Mark commands precisely:

- Current command: verified against the current repository.
- Target verification command: must work after the task is complete.
- Illustrative/provider-specific command: cannot be finalized until a named decision is resolved.

Do not present a target command as if it currently passes. If the tool or provider is unresolved, state the decision or create a spike instead of inventing a command.
